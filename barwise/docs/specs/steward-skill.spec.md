# PR steward skill: repo-specific guidance for agents driving barwise PRs

Status: Implemented (the skill lands alongside this spec)
Created: 2026-08-27
Last-updated: 2026-08-27
Tracking: barwise-876

## Principle

Explicit over implicit. An agent driving a barwise PR to green -- one
watching CI and review events, resolving merge conflicts, pushing
fixes -- operates under a generic harness that knows nothing
repo-specific. The repo's conventions for that job exist, but only as
lived knowledge: how a `.beads/issues.jsonl` conflict is actually
resolved, which files must be regenerated by tooling rather than
edited, what the duplication ratchet does when a fix touches a
tracked literal. The harness looks for exactly one declared home for
this knowledge -- `.claude/skills/steward/SKILL.md` on the PR's head
branch -- and barwise does not provide one, so every PR-driving agent
rediscovers the conventions or violates them.

DRY-secondary bounds the fix: most of what a steward needs is already
owned by CLAUDE.md, AGENTS.md, the check scripts, and the CI
pipeline. A steward skill that restates them is a class-E prose copy
(`docs/logic-duplication-audit-2026-08-26.md`) waiting to drift. The
skill therefore carries only the decisions no other document owns --
the PR-event playbook -- and points at the authorities for everything
else.

## Scope

In scope, stated in EARS form:

- When a PR-driving agent reads the skill before acting on a CI or
  review event, the skill shall give it the conflict-resolution rule
  for `.beads/issues.jsonl` (reconstruct canonical lines and
  validate; never keep merge markers or hand-pick hunks blindly).
- When a conflict or CI failure involves a generated file, the skill
  shall name the regenerator to run instead of a hand edit, or say
  where the authoritative mapping lives.
- When `audit:duplication -- --check` fails on the agent's own
  change, the skill shall state the remedy (classify or remove the
  baseline entry in the same commit).
- When the agent prepares to push a fix, the skill shall give the
  local pre-push gate in CI order and the stale-`dist` trap.
- When the PR merges, the skill shall state the tracker-closure
  convention (a follow-up tracker-only commit, not the code PR).

Out of scope: a `babysit/` variant (the harness prefers `steward/`
when both exist, so one file suffices); any change to CI, scripts, or
CLAUDE.md; posture rules the generic harness already enforces (never
skip a test, never rewrite history on another's branch) -- restating
those adds a copy of an authority the skill cannot override anyway.

## Inventory

| Module                            | Current state                                         | Verdict                            |
| --------------------------------- | ----------------------------------------------------- | ---------------------------------- |
| `.claude/skills/steward/SKILL.md` | Does not exist                                        | New: the skill this spec describes |
| `CLAUDE.md`, `AGENTS.md`          | Own conventions, commands, session-completion rules   | Unchanged; pointed at, not copied  |
| `scripts/*.mjs`, `check-beads.sh` | Own the checks and regenerators                       | Unchanged; named by npm script     |
| `.github/workflows/ci.yml`        | Owns the gate order the skill's pre-push list mirrors | Unchanged; skill cites it as owner |

The pre-push list in the skill is a deliberate prose parallel of the
CI order; it names `ci.yml` as the authority and stays short enough
that staleness is cheap (authoring rule 5, `duplication-audit`
skill).

## Target architecture

```
.claude/skills/steward/SKILL.md
  frontmatter: name, description (when a PR-driving agent should read it)
  1. Tracker conflicts (.beads/issues.jsonl): union by id, latest state,
     canonical lines via scripts/beads-crud.mjs; npm run check:beads -- --strict
     must pass before commit. Duplicate-id from concurrent sessions:
     renumber the newer issue.
  2. Generated files: fix via regenerator, never by hand --
     regen:builtins, regen:examples, regen:tutorial, regen:references,
     UPDATE_GOLDEN=1 for golden tests. Authority: package.json scripts.
  3. The ratchet: audit:duplication --check failing on your own diff;
     update audit-baseline.json in the same commit.
  4. Pre-push gate: the cheap checks in CI order, from barwise/;
     build before any per-package tsc --noEmit (stale-dist trap).
     Authority: .github/workflows/ci.yml.
  5. After merge: close beads issues via beads-crud in a tracker-only
     follow-up; work is not done until pushed.
```

## Alternatives considered

- **Fold it into CLAUDE.md.** CLAUDE.md is loaded by every session;
  the PR-event playbook is only relevant to a PR-driving one, and the
  harness looks for `steward/SKILL.md` specifically -- guidance in
  CLAUDE.md would not be read at the moment it matters. Lost.
- **A comprehensive steward covering all conventions.** Maximizes
  usefulness per read but duplicates CLAUDE.md/AGENTS.md wholesale --
  the exact class-E copy the duplication audit exists to prevent.
  Lost to DRY-secondary's own boundary: unchecked must-agree prose
  does not stay.

### 1. Author the skill

One file, docs-only, no code or CI changes. Lands with this spec in

## Open decisions (for review)

- **Should the prose detector cover `.claude/skills/`?** The
  `audit:duplication` prose detector walks standing docs; the skills
  directory is currently outside its walk, so a parity claim written
  into a skill is not ratcheted. Recommended default: leave as-is for
  now (skills are few and reviewed), and extend the walk if a skill
  ever drifts the way the docs did. Filed as part of this spec's
  review rather than silently decided.

## Risks and testing

- Docs-only: no behavior to test. `npm run fmt` and the docs-only CI
  path gate formatting; `audit:duplication -- --check` confirms the
  new prose introduces no unclassified candidates.
- The main risk is the one the design addresses: the skill going
  stale. Mitigated by pointing at authorities instead of restating
  them, and keeping the one deliberate parallel (the gate order)
  short and owner-cited.

## Non-goals

- No new checks, scripts, or CI steps.
- No restatement of harness posture rules or of CLAUDE.md content.
- No `babysit/` file.
