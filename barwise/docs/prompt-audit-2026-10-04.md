## Summary

Dated prompting patterns (Group 1) hardly appear in the project's own files. The prose is calm, and nearly every emphatic line has its reason next to it. Most of what this audit found is **stale facts and conflicts between instruction files** (Group 2), where code and CI have moved on and the text has not. The highest-impact findings:

1. **CI coverage of the optimizer lane is described wrongly in three places.**
   - Root `CLAUDE.md:184` says "CI does not run it".
   - `optimizer/CLAUDE.md:78-80` and `:252-257` say "nothing else catches a red test".
   - In fact `ci.yml:345` has run `npm run test:optimizer` since 2026-08-29, and the optimizer file's own lines 7-9 say so.
2. **The beads workflow has two contradictory authorities.**
   - `AGENTS.md:23-38` is an older block generated by `bd init`. It prescribes `bd ready`, `bd prime`, `bd update --claim` and `bd remember`.
   - Root `CLAUDE.md:554-580` is newer (2026-09-05). It says the interface is `barwise/scripts/beads-crud.mjs`, that `bd` need not be installed, and that "there is no `remember` subcommand".
   - Five skill sites also call `node scripts/beads-crud.mjs`. That path does not resolve from the repo root.
3. **Checks and facts that agents act on are wrong.**
   - The steward skill names the required CI check `ci (22)`. `ci.yml:14-20` says it is now `ci`.
   - A pr-review checklist item cites an authority header and a code fact that no longer exist.
   - The vscode `CLAUDE.md` describes the LLM-client choice wrongly.
   - The dbt `CLAUDE.md` names `registerBuiltinFormats()`, which no longer exists.

Counts. Project files: 32 findings (31 in the diff, 1 flagged conflict), plus 4 decision flags and about 12 low-confidence flags. User-level skills: 13 findings in the diff, 3 plugin-skill findings reported only, and 7 low-confidence flags.
