## The release downloads run the modeling gym

v2.0.0's three downloads could not run the modeling gym. In
`barwise-cli-2.0.0.cjs`, `barwise gym list` and `barwise gym check`
exited 1 with:

```
Error: The "path" argument must be of type string or an instance of URL. Received undefined
```

`barwise-mcp-2.0.0.cjs` and the MCP server inside
`barwise-vscode-2.0.0.vsix` returned the same error from the `gym_list`
and `gym_check` tools. The bundles could not find the packaged exercise
catalog. The CLI and MCP server built from source were not affected.

2.0.1 fixes it: the exercise catalog is now built into each download, so
the gym works with no extra setup (barwise-fbi).

**If you stay on 2.0.0**, point the gym at a catalog directory yourself:
download `barwise/packages/learn/exercises/` from the v2.0.0 tag and pass
it with `--catalog`:

```
node barwise-cli-2.0.0.cjs gym list --catalog ./exercises
node barwise-cli-2.0.0.cjs gym check customer-order my-model.orm.yaml --catalog ./exercises
```

The MCP tools have no catalog option, so on 2.0.0 the gym is reachable
only through the CLI.

## Also in 2.0.1

The file format, commands and options are the same as 2.0.0. Three
smaller changes reach users:

- **Avro export writes valid field names** when a column is named from an
  unresolved reference mode (such as `(ambiguous)`); 2.0.0 wrote a schema
  Avro parsers refuse.
- **Ossie export reports diagram layouts as lost**, alongside the other
  model content Ossie cannot hold, instead of dropping them silently.
- **`barwise query` sorts names by character code** (uppercase before
  lowercase) rather than by the machine's locale, so its output is the
  same on every machine. A script that depended on the old order may see
  names in a different order.

The rest of the changes since 2.0.0 move code between the internal
packages and add repository checks; the generated changelog below lists
every merged pull request.
