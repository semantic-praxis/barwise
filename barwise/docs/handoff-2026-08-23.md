## Two decisions waiting

### 1. barwise-839 -- remove `orphaned_reference_mode`? (recommend: yes)

It is the entire penalty on all seven recorded answer keys -- 14 of 14
corrections -- and the evidence against it is now four-fold and checked
against source:

- **No validator counterpart.** Every other conformance check exists to
  prevent a specific validator error. Nothing in
  `core/src/validation/rules/` mentions `referenceMode`.
- **Core rates the nearest thing `info`**, which costs zero. Conformance
  charges 0.02 -- more than core charges for the closest real diagnostic.
- **The parser manufactures a reference mode for every entity**, because
  `ObjectType` throws without one. "Has a reference mode" is not
  evidence of anything.
- **It flags what the notation is for.** `Patient (medical_record_number)`
  _is_ the ORM shorthand for the identifier fact type.

It fired 0 times in 15 live dev runs and 14 times across 7 hand-curated
answer keys. That is not the profile of something measuring extraction
quality.

Removing it takes every answer key from 0.94-0.98 to exactly 1.000,
which is arguably the point. It also makes every recorded history row
incomparable, which is why it did not land overnight.

### 2. barwise-842 -- `--provider` is load-bearing and easy to omit

Confirmed against the built resolver:

```
--provider anthropic --model claude-haiku-4-5   ->  haiku45-2
--provider anthropic --model claude-sonnet-5    ->  sonnet5-3
(no --provider)      --model claude-haiku-4-5   ->  DEFAULT ARTIFACT
```

`prompt eval` resolves the artifact from the _flags_. Omitting
`--provider` still builds a working client -- `createLlmClient`
auto-detects from env vars -- but `resolveArtifact` gets
`provider: undefined` and no variant matches. The run then uses the
default prompt while you believe it used the variant.

The client already knows the answer: `LlmClient` declares `provider` and
`model` precisely so a variant can be resolved before the call, and
`processTranscript` resolves from the client. Only this command resolves
from the flags.

Not fixed overnight because resolving from the client would also change
a run that passes neither flag: today that gets the default artifact,
afterwards it would get whichever variant matches the Anthropic default
model. That is a real behaviour change to a plausible command line.

**Until it is decided, always pass `--provider` explicitly.** The
commands below do.
