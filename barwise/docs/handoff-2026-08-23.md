## One decision waiting

### barwise-842 -- `--provider` is load-bearing and easy to omit

Confirmed against the built resolver:

```
--provider anthropic --model claude-haiku-4-5   ->  haiku45-2
--provider anthropic --model claude-sonnet-5    ->  sonnet5-3
(no --provider)      --model claude-haiku-4-5   ->  DEFAULT ARTIFACT
```

`prompt eval` resolves the artifact from the _flags_. Omitting
`--provider` still builds a working client -- `createLlmClient`
auto-detects from env vars -- but `resolveArtifact` gets
`provider: undefined` and no variant matches. The run then uses the
default prompt while you believe it used the variant.

The client already knows the answer: `LlmClient` declares `provider` and
`model` precisely so a variant can be resolved before the call, and
`processTranscript` resolves from the client. Only this command resolves
from the flags.

Not fixed overnight because resolving from the client would also change
a run that passes neither flag: today that gets the default artifact,
afterwards it would get whichever variant matches the Anthropic default
model. That is a real behaviour change to a plausible command line.

**Your point about multi-provider models sharpens the fix rather than
complicating it.** A qwen model can run locally under ollama or hosted
by a cloud provider, and a prompt tuned against one serving path is not
automatically right for the other -- so the model name alone can never
be a sufficient key, and any "fix" that relaxed matching to
`modelPrefix` only would be worse than the bug. The right key is the
(provider, model) pair that will actually serve the call, and the
client is the only thing that knows both: `createLlmClient` has already
resolved the provider and let the provider apply its default model by
the time the artifact is chosen.

That also means the ambiguity you name is a **variant-authoring** rule,
not a resolver one: a variant whose prompt depends on the serving path
must declare `provider:` in its `match:` block, and one that genuinely
travels with the weights may declare `modelPrefix:` alone. Both shipped
variants already declare `provider: anthropic`, so nothing in the repo
relies on the loose form today.

**Until it is decided, always pass `--provider` explicitly.** The
commands below do.
